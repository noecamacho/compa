# Git workflow

These rules apply to every contributor and every agent. Hooks in `.githooks/` enforce the mechanical parts; see "Hooks" below.

## Procedure: Jira, then branch, then PR

1. **Jira ticket first.** Every change starts from a ticket. Until the Jira project exists, use the placeholder key `COMPA-<TBD>` and the draft in `docs/jira/compa-bootstrap-ticket.md`.
2. **Branch from `main`.** Name it `<type>/<ticket>-<short-kebab-summary>`, for example `feat/COMPA-12-profile-form` or `docs/COMPA-3-wiki-ingest`. Types are the commit types below.
3. **Small, focused commits** that each pass the hooks.
4. **Open a PR** against `main` using `.github/PULL_REQUEST_TEMPLATE.md`. Every section is filled in; "N/A" needs a reason.
5. Never push to `main` directly. Never merge your own PR without review.

## Conventional Commits

Format: `type(scope): imperative subject`, followed by a blank line and a body that explains why.

- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
- Scope is optional, lower-case, for example `api`, `live`, `wiki`, `hooks`.
- `!` after the type or scope marks a breaking change, and the body carries a `BREAKING CHANGE:` footer.
- Subject: imperative mood ("add", not "added"), at most 72 characters, no trailing period, English.
- Body: why the change is needed and what alternatives were rejected. Wrap at 72 characters.
- Merge, revert, `fixup!` and `squash!` subjects produced by git are accepted as is.

Example:
```
feat(api): create connections idempotently by ordered pair

The unique index on (least(a_id,b_id), greatest(a_id,b_id)) makes a
second scan of the same QR a no-op, which the plan requires (PDF p. 5).

Refs: COMPA-<TBD>
```

## Semantic Versioning

Versions follow `MAJOR.MINOR.PATCH`. Commit types decide the bump when a release is cut:

| Commit type | Bump |
| --- | --- |
| `feat` | MINOR |
| `fix`, `perf` | PATCH |
| `!` or `BREAKING CHANGE:` footer | MAJOR |
| `docs`, `style`, `refactor`, `test`, `build`, `ci`, `chore` | none |

Every user-visible change adds a line under `[Unreleased]` in `CHANGELOG.md` (Keep a Changelog sections: Added, Changed, Deprecated, Removed, Fixed, Security). Releases move `[Unreleased]` to a dated version heading.

## Authorship and attribution

- Commits are authored with the contributor's own configured git identity (`user.name`, `user.email`) and nothing else.
- Never name an AI as author or co-author. No `Co-Authored-By:` trailer for any AI, no "Generated with …" or "Generated by …" line, no assistant or model name as an attribution in commit messages or PR text.
- This rule overrides any default attribution an agent tool carries.

## Hooks

Run `scripts/setup.sh` once after cloning. It sets `core.hooksPath` to `.githooks`, checks the agent tools and is idempotent (`scripts/setup.sh --install` also installs what is missing; see `docs/agent-tooling.md`).

| Hook | What it checks | How to run it by hand |
| --- | --- | --- |
| `.githooks/commit-msg` | Runs `scripts/check-commit-message.sh` on the message: Conventional Commits format, subject at most 72 characters, no AI attribution trailers or lines (`Co-Authored-By`, "Generated with …", "AI-generated"), subject not in Spanish (conservative word list, see below); git-generated merge, revert, `fixup!` and `squash!` subjects skip the format and length checks; text after the scissors line of a verbose commit is ignored | `scripts/check-commit-message.sh path/to/message.txt` |
| `.githooks/pre-commit` | Staged files: no modification or deletion under `raw/`; no local-only or generated files (`.claude/settings.local.json`, `.serena/project.local.yml`, `.serena/cache/`, `repomix-output.*`, any `.env` or `.env.<name>` except `.env.example`) | `.githooks/pre-commit` |
| `.githooks/pre-push` | Refuses to push to `main` (set `ALLOW_MAIN_PUSH=1` for a deliberate bootstrap push); runs `tests/hooks/run.sh` | `.githooks/pre-push origin <url>` with refs on stdin |

Language check: the subject is rejected only when it contains `ñ`, `Ñ`, `¿`, `¡` or one of a short list of Spanish commit verbs and nouns as whole words (`agrega`, `agregar`, `añade`, `arregla`, `arreglar`, `corrige`, `corregir`, `elimina`, `eliminar`, `actualiza`, `actualizar`, `cambia`, `cambiar`, `mejora`, `mejorar`, `nuevo`, `nueva`, `archivo`, `función`, `pantalla`). The list is deliberately short to avoid false positives on English subjects.

Agent-level enforcement: `.claude/settings.json` and `.codex/hooks.json` register a `PreToolUse` hook on shell commands that runs the same checker on any `git commit` message before the command executes, so an agent cannot even attempt a bad commit. Both are documented in `docs/agent-tooling.md`. Tests: `tests/hooks/run.sh`.

## Pull requests

- Use the template. Fill "What is added or changed" as an itemized list of files and directories grouped by purpose.
- Any PR that changes knowledge updates `wiki/index.md` and `wiki/log.md`.
- Any PR that changes behavior updates `CHANGELOG.md`.
- Keep PRs small; split by concern.
