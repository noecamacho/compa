# Edge cases and risks not yet handled

Date: 2026-10-29 · Baseline: `main` @ `617cb93`, plus the two in-flight branches ([backlog](backlog.md) legend) · Production probed at https://compa.lol.

Each row lists the risk and its impact, how the code handles it today (with the file), a recommendation and the ticket. **Impact** is **H** (harms people, leaks data or breaks the demo), **M** (degrades trust or costs money) or **L** (cosmetic or unlikely). Claims are verified in code unless marked [Inference] or [Unverified]. Related edge cases already covered are in the [gap analysis §3](../backend-gap-analysis.md#3-edge-cases).

## Abuse and safety

| Id | Risk | Impact | Current handling | Recommendation | Ticket |
| --- | --- | --- | --- | --- | --- |
| R-01 | **Spam scanning.** A person, or a script with a session, sends requests to every handle at an event | M | No cap (`createConnection`, `lib/server/connections.ts`). The acceptance step (M6) keeps it from scoring, but the addressee is flooded | Per-user limit per minute and per event; a 429 `rate_limited` code | [T-036](backlog.md#t-036) |
| R-02 | **Fake accounts.** Throwaway LinkedIn accounts farm points or invite rewards | M | LinkedIn-only sign-in (M2) raises the cost. Invite rewards are not live yet (IP) | Invite rewards only for accounts created after the claim; admin ban; review leaderboard outliers | [T-076](backlog.md#t-076), [T-104](backlog.md#t-104) |
| R-03 | **Harassment.** Someone keeps requesting a person, at this event or the next | H | A silent decline (M8) blocks a repeat at that event only. Nothing stops it at the next event. No block, no report | Block (requests fail as "not found", so the block is not revealed); report to admins | [T-041](backlog.md#t-041), [T-042](backlog.md#t-042) |
| R-04 | **Photographed event QR leaks.** A photo of the printed `/e/<code>` QR is shared online, and remote people check in and appear on the big screen | M | IP: the code is unguessable (10 characters, 31-symbol alphabet) and rotatable. Personal-QR auto check-in (A1) bypasses the code entirely | Rotate per event day; show the check-in count to the organizer; decide whether A1 auto check-in also needs the code (OQ #54) | [T-022](backlog.md#t-022), [T-023](backlog.md#t-023) |
| R-05 | **Personal QR screenshot shared** | L | Anyone can send a request; the owner must accept (M6) | Acceptable. Block covers abuse | [T-041](backlog.md#t-041) |
| R-06 | **Minors** | M | LinkedIn requires users to be 16 or older [Unverified for every region]. COMPA states no minimum age. The big screen shows name and photo publicly | State the minimum age in the terms; organizers confirm adult events | [T-102](backlog.md#t-102) |
| R-07 | **An abusive or tracking image on the projector** | H | `PATCH /api/me { photoUrl }` accepts any `z.url()` up to 500 characters (`lib/api/schemas.ts`). The photo is always public (M12) and shown on `/live` | Allow only Storage-origin URLs; admin reset to the monito; hide a person from `/live` | [T-016](backlog.md#t-016), [T-104](backlog.md#t-104) |
| R-08 | **Arbitrary link targets.** The "linkedin" link can point to a phishing site | M | `normalizeLink` keeps any `https?://` value (`lib/links.ts`) | A per-network host allowlist | [T-016](backlog.md#t-016) |

## Concurrency and idempotency

| Id | Risk | Impact | Current handling | Recommendation | Ticket |
| --- | --- | --- | --- | --- | --- |
| R-27 | **Concurrency races** | M | Accept, decline and knew guard on `status = pending`; accept locks `FOR UPDATE`. Mutual scans are absorbed by the unique pair index. Handle insert retries on 23505. IP invite creation falls back on conflict. **Not covered:** a future withdraw vs accept, and the second mutual scanner never learns they are the addressee | Lock on withdraw; a `direction` in the POST response | [T-035](backlog.md#t-035), [T-037](backlog.md#t-037) |
| R-28 | **Idempotency gaps** | M | Idempotent: check-in, scan, accept and decline (409 on replay), approve (409), IP claim. **Not idempotent:** `POST /api/interactions/draft` (a new row and a model call every time), `POST /api/transcribe` | An idempotency key or per-connection cap on drafts; transcribe tied to a connection | [T-052](backlog.md#t-052), [T-057](backlog.md#t-057) |
| R-29 | **The stored status stays `pending` forever** after expiry, because expiry is computed on read and no job runs (`statusForViewer`) | L | Correct for users, misleading for SQL analytics | Document it; or a cron that marks rows expired | [T-103](backlog.md#t-103) |

## Security

| Id | Risk | Impact | Current handling | Recommendation | Ticket |
| --- | --- | --- | --- | --- | --- |
| R-30 | **User enumeration** | M | Any signed-in user can `GET /api/users/{handle}` for any handle; handles derive from names (`lib/handle.ts`). On `main`, the public `GET /api/events/{slug}/live/people/{userId}` returns cards by user id, and the slug is guessable (`founders-fest`, probed 200) | Rate-limit the lookups; scope search to my event; retire the slug routes | [T-034](backlog.md#t-034), [T-036](backlog.md#t-036), [T-092](backlog.md#t-092) |
| R-31 | **Security headers missing** | M | Only `strict-transport-security` (probed). No CSP, `X-Frame-Options` or `frame-ancestors`, `nosniff`, `Referrer-Policy` or `Permissions-Policy` (`next.config.ts` sets none) | Add them in `next.config.ts` `headers()` | [T-005](backlog.md#t-005) |
| R-32 | **CSRF** | L | No Origin or Content-Type check: `readJson` parses `req.text()` whatever the content type (`lib/api/define-route.ts`), so a cross-site `text/plain` form can carry a JSON body. Supabase SSR cookies are `SameSite=Lax` [Inference: `@supabase/ssr` default], so they are not sent on cross-site POSTs | Defense in depth: reject state-changing requests whose `Origin` is not the site origin | [T-005](backlog.md#t-005) |
| R-33 | **Session fixation and the OAuth redirect** | L | PKCE through Supabase `exchangeCodeForSession`. `next` is restricted by `safeNext` (no `//`, no `\`). The session is created only after the code exchange | Keep it; add e2e for `safeNext` | [T-000](backlog.md#t-000), [T-012](backlog.md#t-012) |
| R-34 | **Session refresh** | M | No `proxy.ts` or `middleware.ts`. Server Components cannot write cookies, so an expired access token may not be refreshed until a route handler runs [Inference] | Supabase SSR proxy | [T-006](backlog.md#t-006) |
| R-35 | **RLS reliance** | H | RLS is on with no policies; the server connects with full database credentials and checks authorization in the handlers (§4.7). A handler bug, or a leaked `DATABASE_URL` or service-role key, means full access. The anon key with the Data API is blocked by RLS (good) | Keep keys only in Vercel (captain decision); contract tests on every membership guard; consider per-route least-privilege roles later | [T-000](backlog.md#t-000), [T-007](backlog.md#t-007) |
| R-36 | **Mock mode is reachable in production** | L | `x-compa-mock: 1` makes any production API route return fake examples (probed: `/api/me` returns "Diego Ramírez"). There are no writes and no real data, but fake data can be screenshotted as "real" | Honor the mock headers only when `API_MODE=mock` or outside production. Keep `/api/docs` "try it" working through a docs-only flag | [T-005](backlog.md#t-005) |
| R-37 | **The public Realtime topic is keyed by slug.** `event:<slug>:live` is a public channel; after code gating, anyone who guesses the slug can still subscribe to live connection events [Inference] | M | `liveTopic(slug)` in `lib/realtime.ts` | Key the topic by event id or access code | [T-092](backlog.md#t-092) |
