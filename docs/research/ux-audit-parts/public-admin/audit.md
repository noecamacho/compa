# UX audit: public and operator screens

Date: 2026-10-29 · Ticket: `COMPA-<TBD>` · Baseline: `origin/main` @ `f6f65f3` (PR #46, responsive admin merged) · Scope: landing, `/e/<code>` door, `/e/<code>/join`, `/e/<code>/live`, not-found, `/design`, OG and SEO, and every `/admin` screen.

Related: [backlog](../../../flows/backlog.md), [flow catalog](../../../flows/catalog.md), [DESIGN.md](../../../../DESIGN.md), [new tickets](tickets.md).

## Method

- `API_MODE=mock` dev server on port 3102, run from a scratch copy of the worktree. A sibling dev server already held the worktree's `.next` lock on 3101.
- Playwright 1.48 (Chromium) took viewport-only screenshots at 320×568, 390×844, 430×932, 834×1194, 1440×900 and 1920×1080, plus 2560×1440 for the landing, `/live` and the admin tables. Every shot exists in `es-MX` and `en-US`. Each file is under 250 KB.
- States: a patch to the scratch copy only (`lib/api/mock.ts`, `lib/api/server-fetch.ts`; product code untouched) let one request header turn a server-rendered list `empty`, `big` (400 rows, with every 7th name 58 characters long) or `error` (a 500 from the API). `/live` also has a `stale` state, where polls get a 503.
- A script measured horizontal overflow, page height, the width of the content box and tap targets under 44 px. Every screenshot cited below was looked at.
- Path: `shots/<screen>/<width>x<height>-<locale>[-state].jpg`.

### Limits of this run

- **WebGL.** Headless Chromium could not create a WebGL context, so every `/live` shot shows the no-WebGL fallback instead of the loom. That fallback is itself a finding (P-030). The loom at 1920 was not seen.
- **Mock mode means signed-in Diego.** The signed-out landing (LinkedIn button and note), the signed-out door (LinkedIn, email form) and the real door not-found (any code returns the example event) could not be rendered. They are assessed from code and marked "code".
- **3D hero.** No 3D hero exists on `origin/main`: the landing hero is `components/landing/Crowd.tsx`, CSS-animated pixel monitos. The 3D hero and the responsive passes are in flight on sibling branches. Their findings carry **IF** (in-flight overlap) and must be re-checked against those branches when they merge.
- **`app/live`.** No such route exists on `main` (`/live` returns 404). The big screen is `/e/<code>/live` only.
- The Next.js dev badge ("N", "Issues") in the bottom-left of the shots is dev-only and is ignored.
